# Boundary dataset

Generated by `scripts/generate_synthetic_boundaries.py` — deterministic (fixed random seed),
regenerate any time to reproduce byte-for-byte.

## This is not what Task 1.3d actually asks for

The spec: *"Records real speech (yours, and anyone you can borrow)... a human marks the true
end-of-speech sample index... target >=200 hand-marked boundaries."* That is genuine ground
truth — a person's judgement of when someone finished talking, which is exactly the thing the
endpointing cascade is trying to approximate.

There is no microphone and no human available to sit and label audio interactively in the
environment this repo was built in (the same constraint already documented in
`tests/fixtures/audio/README.md` for Phase 0's fixtures). What's committed here instead is a
**synthetic substitute**: Piper TTS segments spliced together with an exact, programmatically
chosen silence gap, so `true_end_ms` is *known by construction* rather than *judged by ear*.

That is a materially weaker kind of ground truth, in a specific way: it tells you whether the
cascade's arithmetic is correct (does it fire at `silence_ms >= threshold_ms`, do extensions
and caps behave, does a trailing filler actually buy time) but it cannot tell you whether
**350-900ms is the right threshold range for how real people actually pause**, because Piper
speech has none of the breath noise, disfluency or room tone that makes real endpointing hard.
Precision/recall/latency numbers from this set are real, measured numbers — not fabricated —
but treat them as "the cascade implements its own spec correctly," not as "this is what users
will experience."

## What's in it

`labels.jsonl` — 220 items, one `{audio_path, true_end_ms, notes}` row each. `notes` is
`"<case_type>: <params>"`. Case types, each covering a hard case named in Task 1.3d:

| Case type | Count | What it tests |
|---|---|---|
| `clean_definitive_end` | 60 | Baseline: unambiguous complete sentence, no ambiguity |
| `mid_sentence_pause` | 50 | A 400-1500ms thinking pause mid-utterance that is **not** the true end |
| `trailing_filler_then_done` | 20 | Speaker trails off on a filler ("um", "so") and genuinely stops |
| `trailing_filler_then_continues` | 20 | Same trailing filler, but the speaker resumes after a pause |
| `list_with_pauses` | 40 | 3-4 short items (e.g. "Kafka... Postgres... Redis") with pauses between |
| `false_start` | 30 | An aborted opening, a short restart gap, then the real utterance |

Every clip has 1.2s of trailing silence appended after its true end, giving the cascade room
to actually declare an end during evaluation.

## Before trusting any tuning decision made against this set

Run the real thing: `uv run python scripts/collect_boundaries.py --record 20` (or `--review`
against a directory of real recordings), on a real microphone, with real pauses, disfluency
and background noise. `scripts/eval_endpointing.py` runs unchanged against whatever
`labels.jsonl` you point it at — the evaluation code doesn't know or care whether the ground
truth was synthetic or real. Day 11's tuning pass (`docs/phase-1-BUILD.md` TASK 1.3d) should
use real data, supplementing rather than replacing this set once it exists.
